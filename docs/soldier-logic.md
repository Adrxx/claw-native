# Original Soldier logic

`SoldierLogic.h/.cpp` recovers the original Soldier callback `0x48a980`, constructor `0x48aa40`, deleting/destructor methods `0x48afd0/0x48aff0`, class dispatcher `0x48b0c0`, HOME update `0x48b4b0`, firing gate/entry/update `0x48b670/0x48b880/0x48ba00`, and IDLE entry/update `0x48b6b0/0x48b730`. It composes the frozen GenericEnemy, GenericEnemyStates, HumanEnemy, HumanCombat and EnemyMotionAux implementations. Newly required shared entry controllers are separate in `CommonEnemyEntries.h/.cpp`; their coverage is documented in `common-enemy-entries.md`.

The original executable SHA256 is `350b8d51e1cd52037cd31a7722197a815e4206e7d3052ec632465f1354726263`. Soldier registration comes from original literal `0x522d38`, callback `0x48a980`, registry flags zero. Actual class registration `0x48b1d0` first registers Human entries, then installs HOME→`0x48b4b0`, IDLE→`0x48b730`, FIRING→`0x48ba00` in class array `0x53c328`. Numeric IDs and CString data identities come from actual whole `0x401000` bootstrap, rather than an invented Soldier state numbering.

## C API and original storage

`ClawSoldier` uses the frozen `ClawGenericEnemy` snapshot. `ClawSoldierContext` points into caller-owned Human/Combat/Motion views and resolved Soldier class metadata, with explicit difficulty, scene host/container and projectile views. The Human private tail must provide **24 words**, so enemy words 0–263 plus tail words 0–23 represent the exact original **0x480-byte allocation**, 288 words. Human routines use its first 20 tail words. A 20-word Officer allocation is insufficient for Soldier.

The derived fields are announcement latch `+0x450`, shot X/Y offsets `+0x454/+0x458`, signed X velocity `+0x45c`, speech sound `+0x460`, stand-animation timer `+0x464/+0x468`, firing gate timer `+0x46c/+0x470`, and patrol timer `+0x474/+0x478`. The constructor preserves `+0x47c` and every other untouched supplied allocation word; original allocation is not assumed to be zeroed.

`claw_soldier_context_defaults` installs the verified 43-entry vtable `0x50f774` after common defaults. `entry`, `construct` and `tick` operate through the same pointer views. Completion/support is separate from original EAX, and diagnostic faults remain explicit: 1 missing metadata/service/bit backing, 2 missing projectile storage or failed allocation/creation, 3 a propagated Human/Combat/Motion diagnostic. Void routine incidental EAX is not gameplay behavior. Unknown methods return unsupported. The original common typed hit and state controller bodies retain their own view requirements.

At dependency boundaries the host must commit/reload the actor 128-word, primary/secondary/contact 93-word, and full private 264+24 views, player/attacker/platform and effect buffers, with the supplied token identities. The normal alias profile is the actual constructed object: actor `+0x6c` names the primary, primary `+0x18` names the private allocation, and private actor/logic wrappers refer to that same actor/primary. Name tokens must retain copied registry CString identity. Text equality cannot replace Human pre-update's comparisons to original literal addresses.

## Constructor and callback

Startup state 0 changes primary state to 1000 before allocating 0x480 bytes. It constructs, invokes the actual virtual `+0x10`, then commits private token to primary `+0x18`. State 29 invokes virtual `+0x20`, state 30 invokes `+0x1c`, state 1000 skips, and every other state executes frozen common scheduler `0x4dc870`. Normal wrapper EAX is 1. Failed allocation has no normal original return: the original dereferences zero at `0x48a9de`; the portable API reports fault 2 with the same pre-fault actor/logic mutations.

Constructor first executes frozen Human `0x44c000`, then zeros exactly `+0x464` through `+0x478`, installs Soldier vtable, chooses LEVEL_SOLDIER images and sets bit 8. Inline bitsets are updated directly; larger bitsets use supplied backing. An undersized size at most 8 makes the exact `0x4dbd20(private+0x2f4,8)` growth dependency, whose allocation behavior remains external.

Seventeen sequence lookups are retained in order, including duplicated FALL and LIFTED2 lookups and fallback GAME_NULL on each missing sequence. Their fields are `308/30c/310/370/318/31c/32c/374/334/338/33c/344/34c/378/37c/380/36c`. Seven sound lookups populate `3a4/410/414/418/3a0/3b4/460`; the exact original names include LEVEL_SOLDIER_RFHEADBT8-22 and LEVEL_SOLDIER_SOLGUNFR8-22, with hyphens.

Soldier sets its attack/private movement rectangles, actor movement `(-11,-60,11,50)` and hit `(-15,-50,15,50)`, region ranges `(400,50),(300,50),(300,50),(80,50),(80,50)`, and original auxiliary offsets. Range is 25×rangeScale with unsigned minimum 99. Health is 3 on difficulty 1, otherwise 7, then healthScale; damage is 10×damageScale. The original CRT precision 53 and signed float conversions are preserved by the frozen common layer and bounded derived scaling. Finally it subtracts 32 from actor Y, invokes ground placement `0x4cd800(tileManager,actor,0)`, sets actor mode 1 and enters IDLE.

## HOME, IDLE and FIRING

HOME first mirrors according to direction `+0x18c` and consumes a discarded RNG value. Regions 3/4 invoke virtual `+0x58` (the recovered common STRIKE entry) and return. Regions 0/1/2 test the exact horizontal-clear/player-height gate; a failed gate invokes IDLE. The once-only speech cue is attempted before setting latch `+0x450`. A second gate selects shared Human HOME update or Soldier firing gate. The horizontal tests preserve repeated calls, signed strict Y comparisons, source actor identity and exclusion of level word `0x26b7`.

IDLE entry zeros X velocity, saves the old state, resolves LS_IDLE, saves/selects/advances ANI, then retains its actual ordering: patrol duration 4000 and start tick are written before animation advance. IDLE update uses unsigned elapsed timers. Every 1000 ms it consumes signed RNG modulo 2; negative odd remainders skip animation selection. Player visibility invokes HOME; otherwise an expired patrol timer, zero countdown `0x541334`, and signed RNG modulo 100 below 5 invoke shared patrol. Firing gate uses unsigned elapsed comparison, then enters FIRING and writes duration 500/start tick after entry returns.

FIRING entry saves the old state, resolves LS_FIRING and mirrors. Difficulty 2 with a crouching player selects LEVEL_SOLDIER_STRIKE2; other profiles select LEVEL_SOLDIER_STRIKE, with exact fallback. Left-facing render bit 2 sets X offset +65 and velocity +500; the opposite profile uses -65/-500. Crouching difficulty-2 Y offset is +10; other profiles use -38. It saves/selects the sequence and clears the fired latch `+0x1a0`.

FIRING update advances animation first and fires only when that result equals 1 and the live latch is zero. It sets the latch before creating Bullet, using container, ID 0, actor coordinates plus offsets, wrapped depth minus 1, literal `0x522e0c`, and flags `0x40000`. It chooses LEVEL_MUSKETBALL, sets damage 10/type `0x40`, and invokes the returned actor's actual primary `+0x10` callback as cdecl(actor). **After callback completion**, it reloads primary/private identities, stores signed velocity as double, zeros Y velocity and gravity, and mirrors negative-velocity projectile rectangles in the original order. Live audio gate/volume and the sound pool then drive playback. A completed ANI with no delay invokes HOME after firing work.

With `scene.lookup`, creation composes frozen SceneActorRuntime and projectile writes use live raw heap spans. Otherwise the exact creator/callback services refresh `bulletToken`, actor/primary/private pointer views. At least 81 private words are needed for the fields actually read; this is a view-capacity requirement, not a recovered Bullet allocation size. The comparison preserves a wider 92-word fixture. The Bullet callback `0x40fec0`, its physics/update/impact/lifetime and native playback remain explicit services. A zero creator matches the original null image-access prefix at `0x4c797c`; it is reported as fault 2.

## Verification and remaining boundaries

`Tests/compare_soldier_logic.py` passes **1,992 whole original calls**, **19,407 ordered complete-snapshot service events**, and **5,740 original instruction addresses**, plus two separately counted failed allocation/creation prefixes with three matching service events. Every normal call compares all actor/primary/secondary/contact/private words, the complete 24-word tail, player/attacker/private/platform/effect views, bit backing and relevant live globals. Ordered events include those same snapshots. All 84 captured registry tables and the entire 1 MiB original registry heap remain unchanged. Bootstrap uses actual whole `0x401000` and actual `0x441030` getters to clear used tables' temporary counts; nonempty name data tokens differ from original literals.

Seeded cases cover each derived/common body, resources missing/present/fallback, difficulty and finite scales, signed RNG boundary values, wrapping clocks, mirroring sentinels, callback mutation, variable bitset storage/growth and deleting flags. Directed common movement probes include supported floors and rejected wall-top geometry. Normal null-page SEH storage is an explicit fixture; failure prefixes unmap null and install FS/TEB/GDT descriptors so the original fails at the actual dereference.

All **16 actual Level 1 Soldier WWD records** run startup and retained idle→firing→Bullet initialization→whole LogicHit→duplicate rejection→repeated shots→automatic death chains. Each produces exactly one `0x42df90` loot handoff; re-entering death mode 1 retains the original bit-4 loot gate, followed by 999/1000/1001 ms expiry checks. The original executes whole ground `0x4cd800`, motion `0x4cbb60`, horizontal-clear `0x4cda10` and ledge/point routines against the actual Action-plane tiles/descriptions. Native uses the frozen CollisionResponse/EnemyMotionAux implementations. Geometry leaves' internal point calls are inside the recovered service boundary; Soldier's direct ledge/move-ahead point calls retain individual ordered events.

WWD SHA256 is `b243d4615172b0764f06ea2a11e672ee60052831694ad238e1c8db73ac055557`. Raw profiles are saved in `work/soldier-agent/actual-level1-profiles.json`, final histories/counts in `verification.json`, and logs in `test.log` and `common-test.log`. Production C++ passes `-Wall -Wextra -Werror -ffp-contract=off`; both headers pass C11 syntax/ABI declarations. No shared project, renderer, native audio, Xcode or devices were changed.

Loot `0x42df90` is the exact frozen WorldLoot host handoff in this suite; its drop body and spawned Goodie gameplay are independently recovered modules, and their whole execution is not claimed by these Soldier chains. Root must commit the raw inventory wrapper and compose that runtime. Resource/ANI services, speech/audio playback, hit particle `0x461a00`, Bullet callback/lifetime, bitset heap growth/destruction and the multi-argument strike overloads `0x43ee10/0x43eee0` remain explicit boundaries. The complete ordinary Soldier vtable/controller layer is represented, but these external services prevent a whole-game parity claim.

Recovery logs for verified wrapper, constructor, states and common entries are clean. One rejected exploratory request `0x48b200` was recognized as an interior of actual registration `0x48b1d0`, discarded and retained only in `rejected-interior-ghidra.log`; no implementation uses it as an entry.
