# Original remaining compressed eight-bit effects

`EffectPIDBlitter` recovers modes 4, 8, 22 and 50 of the original compressed eight-bit pixel bodies. Modes 1 and 2 compose frozen `LightPIDBlitter` and `PIDBlitter`, without modifying or duplicating their pixel implementations. The new finite scan preserves the common source branches needed by the remaining effects. Physical DirectDraw lock/unlock and indexed-frame presentation are separate transport/integration boundaries.

All original comparisons use the pinned unmodified v1.0 executable, SHA-256 `350b8d51e1cd52037cd31a7722197a815e4206e7d3052ec632465f1354726263`. Retail assets have the separately pinned archive identity used by the existing loaders; identity against the v1.0 asset installation is not inferred. No reference gameplay/pixel implementation is used.

## ABI and source election

The public entry uses the frozen `ClawPIDBlitCommand`, `ClawLightPIDBlitState`, `ClawLightPIDBlitTable` and `ClawLightPIDBlitInfo` types. `claw_effect_pid_blit8` adds an explicit `scratchCapacity` after the scratch pointer. Provide **129 live bytes** from source global `542bb0` for the new families. This is deliberate: a mirrored mode-50 literal of length 127 reads scratch byte 128, beyond the frozen lighting body's 128-byte requirement. The extra byte is retained input state, not newly zeroed padding.

Whole dispatcher `4bffa0` is thiscall ECX=40-byte compressed object with five arguments `(destinationRect,surface,sourceRect,flipX,flipY)`, RET 20. Modes other than 1 require compressed `+24` low byte one. The four elected table bodies are `4c1190` (no flip), `4c25b0` (X), `4c3800` (Y), and `4c4c20` (XY), all thiscall three-argument bodies, RET 12. Mirrored clipped-right paths reach `4c5e80` for the same effect-specific reverse stores.

Compressed state is `+0` render word, `+14` mode, `+18` effect value, `+1c` table object, and `+24` format byte. Width/height and encoded bytes are supplied by the already recovered PID loader. The table object is three words `{active,byteLength,payloadToken}`; the source bodies read its payload at `+8` and ignore active/length. Native `data/capacity` supplies that token's exact mapped span. A null table object is accepted without locking/writing even in fill mode; mode 22 can have a null payload because it does not dereference it.

## Actual pixel operations

`old` denotes the source run's destination snapshot, `src` a literal byte, `value` the original unsigned 32-bit effect word, and `T` the payload. Source pointer addition wraps as x86 32-bit arithmetic; native capacity validation is a separate safety extension.

| Mode | Exact finite operation |
| --- | --- |
| 4 | `T[(old << 8) + value]` |
| 8 | `T[(src << 8) + value]` |
| 22 / `0x16` | Write `value & 255` |
| 50 / `0x32` | `a=T[256+old]`, `b=T[256+src]`; signed wrapping product `(b-a)*value`, signed division by 255 truncating toward zero, then forward-table index `a+quotient` |

Mode 50 therefore uses the actual 512-byte rank/inverse table generated by `4c6fa0`; it does not average RGB channels or use host floating-point opacity. The implementation preserves the 32-bit wrapping multiply before division. Coefficients outside ordinary bounds can elect addresses outside the allocation; native rejection does not claim an original clean return for those profiles. A valid in-span index into the second half remains allowed, since the source has no invented clamp to 0..255.

Modes 4 and 50 snapshot destination bytes into `542bb0`, preserving its unmodified tail. Modes 8 and 22 do not modify that scratch at all. Literal zero is a real store in every mode; high-bit transparent runs skip stores and scratch writes. Horizontal position retains the original +1 column and source branch quirks, including bottom-row exclusions, ignored clipped-right fields and physical neighboring-row/padding spills documented in `light-pid-blitter.md`.

Two additional source quirks are material:

- Mirrored mode 50 copies `count` destination bytes beginning at `destination-count-1`, then consumes scratch bytes `count+1, count, ..., 2`. The first two are stale tail entries, and the captured pixels begin two columns earlier than the ordinary reverse snapshot. This occurs in the inline reverse branches and `4c5e80`. A length-127 run requires scratch byte 128.
- Mode 4 with nonzero render word elects odd `(sourceScanRow + destination.top)` rows. Forward draws write the fixed-effect result to both the current address and `+stride`. Mirrored draws use the fixed effect for the primary row, but the second-row lookup uses **the first literal of that run repeatedly**: its source pointer does not advance. Both rows use the same original primary-row destination snapshot. Vertical flip still writes the second result at `+stride`, despite scanning toward lower row addresses.

Modes 8, 22 and 50 ignore that alternate-row gate. The XY top-skip local counter remains the same uninitialized source stack word as the table lighting family; the explicit `bothTopSkipSeed` preserves it. Its zero initialization is a declared native caller-stack profile, not a universal original guarantee.

## Tables, actual caller fixtures and safety

Table capacity is dynamic. Tests use all 42 actual LIGHT/AVERAGE/SHADE CLTs with their actual payload lengths (64 KiB / 64 KiB / 16 KiB). SHADE fixtures constrain reachable mode-4 destination and mode-8 source indices to the actual 16 KiB allocation. This is a bounded source-body index profile, not a claim that ordinary player sprites automatically elect that table in gameplay.

`rank-fixtures.py` executes the complete original `4c6fa0` and original CRT sorting/helpers for all 14 MAIN palettes, adapting only allocation/free, and records all resulting 512 bytes. MAIN's final 768-byte triples are expanded with fourth byte zero according to verified loader instruction evidence. Physical palette `GetEntries` remains the declared transport profile, not a recovered source PAL/DirectDraw implementation. The 14 captured outputs and allocation identities are in `ranks.json`.

Player format fixtures select image-command 3's parameter from actual STAND, WALK and POWERUPSWIPE ANI records: 26 records, 22 distinct PIDs. Frozen `AnimationEngine` remains responsible for original record/control/timing behavior; this worker's record inventory is a format adapter, not a new whole animation-state recovery. The frozen player `420070` effect cycle elects mode 4 and values `0x34/0x35/0x36/0x37/0x65/0x34`; retained tests use those real values. Mode 8/22/50 sprite draws are finite pixel profiles without invented caller powerup election.

Input/output/table/scratch/coverage buffers must not alias. Validate against the complete physical indexed framebuffer, not a guessed nominal rectangle. Return zero can denote source rejection, unsupported mode/format, or native malformed/bounds rejection; rejected buffers and info remain untouched. Accepted null-table profiles report zero lock/unlock/writes. Unknown mode numbers and other pixel depths remain explicit unsupported boundaries, although the original dispatcher can accept unknown table modes with no literal stores. Native temporary copies make safety rejection atomic; their allocation behavior is not an original heap claim.

The source lock `4b9730(surface,0)` and DD interface virtual `+80` unlock `(dd,0)` remain physical services. Caller-visible count/coverage describe original writes; `Info.consumed` is only a native cursor diagnostic. Presentation must blend into the current indexed frame and use its complete visible covered buffer, followed by palette conversion in the separate native backend.

## Verification

The main whole-original suite passes **13,276 paired dispatcher calls**, **26,512 ordered full lock/unlock snapshots**, **7,639,666 actual byte stores**, and **5,438 distinct original instruction addresses**, excluding adapted lock/unlock and harness stop. It compares a complete 1 MiB heap and 320 KiB global image while permitting only destination and 129-byte scratch stores. Full raw receiver, rectangles, encoded input, table object/payload and unrelated state remain unchanged. Complete buffers, padding, guards, actual-write coverage, repeated store counts and scratch tails are compared.

Coverage includes all four modes/flips/render-word branches and the complete 7×4 clip matrix; maximal 127-byte literals; numeric wrapping profiles; all 42 actual CLTs and 14 source rank profiles; 180 generated grammar/overlapping-stride cases per mode; 2,112 actual player full/clipped draws across 22 PIDs; 416 paired retained same-PID draws; accepted null-table and zero-payload fill; and frozen normal/light delegation.

`retained-ani-check.py` separately passes **208 continuous source/native draws with 416 snapshots**, changing actual ANI frame IDs and cycling effects while keeping the same 256-stride, 40,960-byte indexed framebuffer and scratch. Its 1,028-address count is separate and not added as a disjoint union. This checks changing-image pixel history, not original game frame scheduling.

Strict C11 and Swift import/link checks and **384 additional whole-original-derived exact-buffer fixtures** pass ASAN/UBSAN. Guarded allocations cover 512/65,536-byte tables, maximal run scratch byte 128, input, framebuffer and coverage, plus malformed/index/short-scratch atomic rejections. Commands and evidence live in `work/effect-pid-blit-agent`, with final main counts in `verification.json`. No Xcode build, native UI, device or physical graphics acceptance is performed by this worker; these finite source comparisons do not establish complete-game equivalence.
