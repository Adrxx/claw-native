# Captain Claw reconstruction: entry point for every agent

Goal: the original, unmodified single-player Captain Claw, running natively on a 13-inch M5 iPad Pro, behaving like the original. Custom levels (such as those on the Claw Recluse site) are supported through the original Load Custom Level path, including the CrazyHook level features that do not need Windows plugin code (owner decision 2026-11-02); plugin/DLL-only features show a clear unsupported message instead of loading.

Read `docs/OPERATING.md` next. It is short and it is the whole operating manual. Then run `make next` and do that one task.

Read per-family documents in `docs/` only when the task names them.

## Rules that always apply

- One task per session. Take it with `make take ID=<id>`. When it is done or blocked, record it with `make finish` or `make block` and end the session. A fresh session takes the next task.
- Original binaries, extracted assets and anything derived from them stay local. Never commit or upload `Original/`, `App/GameData/` or `work/`. Never paste decompiled or disassembled text into a tracked file.
- Exceptions (owner decision 2026-11-07): the data tables the app build takes from `CLAW.EXE` (menu text, key bindings, font, program metadata, level data) may be tracked in `App/OriginalTables/`, and the community CrazyHook compatibility helpers in `App/CrazyHookHelpers/`, so a player needs only the disc `CLAW.REZ`. Screenshots and short clips of the running game for the README may be tracked in `docs/media/`. The EXE itself, the REZ and all other movies, music, sounds, images and levels stay untracked.
- The platform layer (Windows, DirectX, the C runtime, MFC) is replaced by native code, not recovered. Recover game code only.
- The admission gate decides what counts as verified. Do not build other certification on top of it.
- Change only what your task needs. Never edit a family's specification, test cases or fixtures to make a comparison pass.
- The agent holding a queue task may build and run the Mac app. Sub-agents never run `xcodebuild`. Coordinate shared simulators and devices before using them.
- Keep heavy local jobs to four at a time. Higher concurrency can overload the build machine.
- Do not commit or push unless the owner asks.

## Where things are

- `make help`: every command. Each prints one line of JSON last.
- `tools/queue.json`: the task queue. `make next` shows the next task.
- `docs/STATUS.md`: where every family stands, generated by `make status`.
- `docs/PLATFORM-BOUNDARY.md`: what game code needs from the native platform layer, generated.
- `docs/GLOSSARY.md`, `docs/ADMISSION.md`, `Tests/clawparity/README.md`: vocabulary, admission rules, how to write a module and its tests.
